# Open-source ideas: HyperFrames, Remotion, and the tools Briefcut credits

Checked on 2026-11-04 against the tree on branch `briefcut-demo-polish`. The question was: "use HyperFrames or Remotion as well. Are all their best features added to this repository right now?"

**Short answer: no.** Briefcut does not use HyperFrames or Remotion, and it does not render HTML or React. Of the 32 features listed below, 10 are in Briefcut, 11 are in part, and 11 are not. The ones not taken are the browser runtime itself (HTML or React compositions, animation libraries, an embeddable player), cloud fan-out rendering, the block catalogue, and the HeyGen media models that the Meta-only rule keeps out. Each verdict names the Briefcut file that holds the feature, or says why it is missing.

## How to read this

- **Taken**: the feature exists in Briefcut at the file paths given. Each path was opened on 2026-11-04.
- **Partly**: part of it exists. The row says what is there and what is missing.
- **Not taken**: it is not in Briefcut. The row says why: scope, time, license, or the Meta-only rule.

Three Briefcut rules decide many of the verdicts. Models return bounded data and no model output is run as code ([ARCHITECTURE.md section 12](../ARCHITECTURE.md#12-invariants)). Only `meta.py` reaches beyond this machine, and only to `api.meta.ai` ([ARCHITECTURE.md section 12](../ARCHITECTURE.md#12-invariants)). The render happens on your own computer and originals never leave it ([PRIVACY.md](PRIVACY.md)).

## HyperFrames by HeyGen

**Where HyperFrames is used today:** not in the product, but in the demo film. The explainer cards in the hackathon video (the hook, the hackathon timeline, the four "why Meta" cards, the film-strip collapse, the number cards and the Muse Code tool chain) are HTML compositions rendered to 1080p MP4 by HyperFrames itself, under its Apache-2.0 license. That is a fair test of the integration sketched at the end of this page.

### Facts checked

- Official repository: [github.com/heygen-com/hyperframes](https://github.com/heygen-com/hyperframes). GitHub reports 78,910 stars, created 2026-03-10, latest release [v0.9.13](https://github.com/heygen-com/hyperframes/releases/tag/v0.9.13) on 2026-11-04 (checked with `gh api`).
- **License: Apache License 2.0.** The [LICENSE](https://github.com/heygen-com/hyperframes/blob/main/LICENSE) file sits at the repository root, and the GitHub license API returns `Apache-2.0`. The README says "no per-render fees or commercial-use thresholds" ([README, Why HyperFrames?](https://github.com/heygen-com/hyperframes#why-hyperframes)).
- The repository named in the question, [github.com/hyperframes/hyperframes](https://github.com/hyperframes/hyperframes), is not the project. It holds one README and no license file, has 6 stars, and links to `heygen-com/hyperframes` as "the open-source project". Its docs link, `hyperframes.app`, answered `curl` with a Cloudflare challenge page. The official docs are at [hyperframes.heygen.com](https://hyperframes.heygen.com/introduction) and in the repository under [docs/](https://github.com/heygen-com/hyperframes/tree/main/docs). The facts below come from those files.
- Requirements: Node.js 22 or later and FFmpeg ([README, Manually with the CLI](https://github.com/heygen-com/hyperframes#manually-with-the-cli)). The renderer seeks each frame in headless Chrome and encodes with FFmpeg ([README, How It Works](https://github.com/heygen-com/hyperframes#how-it-works)).
- The desktop Studio app is free. Its Pro plan adds HeyGen's video, image, voice and music models ([README](https://github.com/heygen-com/hyperframes#readme)).

## Remotion

### Facts checked

- Repository: [github.com/remotion-dev/remotion](https://github.com/remotion-dev/remotion). GitHub reports 70,743 stars and the latest release [v4.0.540](https://github.com/remotion-dev/remotion/releases/tag/v4.0.540) on 2026-11-02 (`gh api`).
- **License: the Remotion License, which is not an OSI license.** GitHub classifies it as "Other". [LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) has two tiers. The Free License covers an individual, a for-profit organization with up to 3 employees, a non-profit, or someone evaluating. **The company-license rule:** everyone else "is required to obtain a Company License", bought at [remotion.pro](https://www.remotion.pro/license). The free tier also forbids copying or modifying Remotion to sell a derivative. The file says the license will change slightly in Remotion 5.0 ([PR 3750](https://github.com/remotion-dev/remotion/pull/3750)). The docs index for licensing is [remotion.dev/docs/license](https://www.remotion.dev/docs/license).
- What it is: "give you a frame number and a blank canvas, to which you can render anything you want using React" ([The fundamentals](https://www.remotion.dev/docs/the-fundamentals)). Rendering is headless Chrome plus FFmpeg, as in HyperFrames ([HyperFrames vs Remotion](https://github.com/heygen-com/hyperframes/blob/main/docs/guides/hyperframes-vs-remotion.mdx)).
- Briefcut is published by Aubric, Inc. under the GNU AGPL-3.0 ([LICENSE](../LICENSE)). Whether Aubric would fall under the Remotion company tier was not checked here. It depends on headcount and is the user's decision.

## Count

Across H1 to H17 and R1 to R15: **10 Taken, 11 Partly, 11 Not taken.** The pattern is plain. Briefcut took the workflow ideas (a declarative program, a CLI, a preview editor, captions, skills and MCP) and left the browser runtime and the cloud fan-out. That is a choice, not an oversight. Briefcut edits real footage with FFmpeg and Meta's models, and it promises that the render stays on your computer.

## What a HyperFrames integration would look like

An `html_card` op would join `OPS` in [`src/vedit/compile.py`](../src/vedit/compile.py) beside `motion_card`, and its spec would pass through [`src/vedit/edit_spec.py`](../src/vedit/edit_spec.py) under the motion card's bounds: at most 5 words and 28 characters of text, a 48-character subtitle, 1.5 to 4 seconds, and closed lists for kind, style, palette and camera. The HTML would be a few card templates that Briefcut owns, stored beside [`src/vedit/assets/blender/motion_card.py`](../src/vedit/assets/blender/motion_card.py), and the validated words would be set as text content only, never as markup, so no model output reaches the page as code. A render step would run `npx hyperframes render --format mov` on that template with a transparent stage, which HyperFrames documents as a ProRes 4444 overlay with alpha ([rendering guide](https://github.com/heygen-com/hyperframes/blob/main/docs/guides/rendering.mdx)), and the result would be cached by the hash of the spec and the template bytes exactly as [`src/vedit/blender_cards.py`](../src/vedit/blender_cards.py) caches a Blender card. The compiler would lay the `.mov` over the opening or closing seconds through the existing `card_filter` overlay on the output clock, so [`src/vedit/timeline.py`](../src/vedit/timeline.py) never moves and the receipts in `report.json` still probe the delivered file. The op would be offered only when `capabilities()` in [`src/vedit/campaign.py`](../src/vedit/campaign.py) finds Node 22 and the HyperFrames CLI on the machine, as it does for Blender today, and it would cost no Meta call beyond the words Muse Spark already proposes, which keeps the Meta-only rule and the Apache-2.0 license both intact.
